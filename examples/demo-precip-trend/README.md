# Synthetic example: request → contract → execution facts → presentation

This example uses invented station data and output paths. It demonstrates the safety
boundaries of the workflow; it does not include real data, locations, or results.

1. [00-rough-task.md](00-rough-task.md) is the starting request.
2. [01-plan.md](01-plan.md) is an approved `TASK_CONTRACT.md`. It includes explicit
   Non-Goals and a numeric Scope Budget.
3. [02-notes.md](02-notes.md) shows the records produced by `3-conduct-plan`: observed
   execution and validation facts only—no scientific interpretation.
4. [03-storyboard.md](03-storyboard.md) is a later, explicitly requested communication
   artifact. It is designed only after a separate reporting/interpretation stage has
   been approved.

The key boundary is intentional: a request for execution and a request for interpretation
are two different approvals.
